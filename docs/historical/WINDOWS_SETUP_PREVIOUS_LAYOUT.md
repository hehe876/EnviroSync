# Windows 11 — fresh modular repository setup

## Recommended: leave your old folder intact

1. Back up your existing `C:\Users\San\EnviroSync` folder, especially `.env`, `.git`, notes and preview data. **Never copy `.venv`, `.aws`, AWS credentials or Git history into a new source archive.**
2. Extract the delivered ZIP **into a new directory**. Example: `C:\Users\San\EnviroSync-Modular`. Open the included `EnviroSync` project folder in VS Code; you should see `pyproject.toml` in its root.
3. Use `Terminal -> New Terminal` and select PowerShell. All commands below are run from that root.

## Recommended one-command install

```powershell
.\scripts\setup.ps1
```

This creates `.venv`, installs all dependencies and runs offline tests, without AWS credentials. Make sure `py -3.12 --version` succeeds first.

## Manual fallback (no PowerShell execution policy changes)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -c "from enviro_sync.api import app; print('IMPORT OK')"
.\.venv\Scripts\python.exe -m uvicorn enviro_sync.api:app --host 127.0.0.1 --port 8000
```

If `.env` exists, **don't overwrite it**. Replace the placeholder bucket names with your existing Milestone 1A bucket names before live reads/writes. No AWS credentials belong in `.env`.

To show the interpreter used, run:

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
```

It should point to this repository's `.venv`. A terminal activation is optional; always using `.\.venv\Scripts\python.exe` avoids the system-Python/Pytest mismatch you saw earlier. You do **not** need a `PYTHONPATH` environment variable because `pip install -e ".[dev]"` registers `src/` as an editable package.

## Verify API and tests

Terminal A:

```powershell
.\.venv\Scripts\python.exe -m uvicorn enviro_sync.api:app --host 127.0.0.1 --port 8000
```

Terminal B:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
.\.venv\Scripts\python.exe -m pytest -v
```

`/api/health` has no S3 dependency; real endpoint reads are separate and may incur AWS charges. Press `Ctrl+C` in Terminal A to stop.

## Common errors

- `No module named pytest`: your `python` is not the installed venv. Use `.\.venv\Scripts\python.exe -m pytest`.
- `No module named enviro_sync`: install from repository root with `.\.venv\Scripts\python.exe -m pip install -e ".[dev]"`.
- `No module named dotenv`: dependency install incomplete; retry `-m pip install -e ".[dev]"`.
- `file or directory not found: tests`: you are in the wrong directory. Run `Get-Location` and `Get-ChildItem pyproject.toml, tests`.
- `CONFIGURATION_ERROR`: bucket names or region env values missing/invalid; edit `.env`.
- `AWS_REQUEST_FAILED`: real API couldn't access S3, or objects were not published; check IAM, regions and catalog, not just `/api/health`.
- `npm` missing or PowerShell blocks `npm.ps1`: install Node.js 22 LTS, restart VS Code, and use `npm.cmd` as the supplied PowerShell scripts do.
- Vite UI loads but says catalog unavailable: check Python API, root `.env`, published catalog and AWS credentials. `/api/health` does not test AWS.

## Integrated React frontend (included)

No `npm create vite` command is needed; the React app already exists inside `frontend/`. Install it once from the repository root:

```powershell
.\scripts\setup-frontend.ps1
```

Open **two separate VS Code PowerShell terminals**, both in the repository root:

```powershell
# First terminal
.\scripts\start-api.ps1
```

```powershell
# Second terminal
.\scripts\start-frontend.ps1
```

Open http://127.0.0.1:5173. For a full offline check, stop both servers or open a third terminal and run:

```powershell
.\scripts\check-fullstack.ps1
```

`frontend/node_modules` and `frontend/dist` are generated automatically, and they must **not** be committed. Commit the new `frontend/package-lock.json` generated by the first `npm install` to support reproducible GitHub builds. The current GitHub Actions uses `npm install` because the build environment in which this archive was written couldn't access npm registry; switch to `npm ci` in Actions once the lockfile is committed.
